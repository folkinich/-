# Backend «Собрались»: вход и почта

Python 3.11+ и SQLite; дополнительных Python-пакетов не требуется.
Сервер использует HTTPS API Resend. SMTP здесь не используется.

## Первый запуск в PowerShell

Разместите два репозитория рядом:

```
EventFlow/
  frontend/   # HTML, CSS, JS из frontend-части архива
  backend/    # server.py и файлы backend-части
```

В папке backend выполните:

```powershell
Copy-Item .env.example .env
notepad .env
python server.py
```

Если `.env` уже есть, сохраните его и внесите только недостающие настройки.
Существующий `data.sqlite3` не удаляйте и не заменяйте: в нём ваши аккаунты.
Этот архив базы данных не содержит. При первом запуске без базы создаётся новая.

Откройте `http://localhost:3001`. Сервер сам выдаёт файлы из `../frontend`.
`FRONTEND_DIR` можно изменить на другой путь; относительный путь считается от backend.
Не открывайте HTML двойным щелчком как `file://`.

## Настоящая отправка писем через Resend

1. Создайте аккаунт Resend и добавьте свой домен в Domains.
2. У регистратора домена добавьте DNS-записи, которые показывает Resend, и дождитесь подтверждения.
3. Создайте API-ключ с правом отправки с нужного домена.
4. Заполните **локальный** `.env`:
   - `RESEND_API_KEY` — ключ Resend;
   - `EMAIL_FROM` — например `Sobralis <hello@your-verified-domain.example>`;
   - `SUPPORT_EMAIL` — настоящий адрес, на который должны приходить обращения;
   - `BASE_URL` — адрес этого backend, доступный тому, кто открывает письмо;
   - `FRONTEND_URL` — адрес frontend, куда вернётся пользователь после подтверждения.
5. Перезапустите сервер после изменения `.env`.

Без своего подтверждённого домена Resend допускает только ограниченное тестирование:
используйте разрешённого сервисом тестового отправителя и адрес получателя,
разрешённый в вашем аккаунте. Это не режим для рассылки всем участникам.
Не обходите ограничения отправителя или получателей.

Не отправляйте ключи в чат и не сохраняйте `.env` в Git.
Без ключа и отправителя регистрация вернёт понятную ошибку 503 и не создаст аккаунт.
Форма поддержки также требует `SUPPORT_EMAIL`.

## Проверка почты вручную

1. Зарегистрируйте тестового участника на свой адрес.
2. Убедитесь, что до подтверждения войти нельзя.
3. Откройте последнюю ссылку из письма в течение 24 часов.
4. Проверьте сообщение «Почта подтверждена», войдите и выйдите.
5. При необходимости на странице входа укажите почту и пароль и нажмите
   «Отправить письмо повторно». Между повторными отправками — минимум минута.
6. Отправьте тестовое обращение и проверьте `SUPPORT_EMAIL`.

Ответ API означает, что Resend принял письмо, а не что оно дошло до папки «Входящие».
Если письма нет, проверьте Spam и статус отправки/отказа в панели Resend.

При сбое почты после создания аккаунт остаётся неподтверждённым:
не регистрируйтесь повторно, используйте повторную отправку со страницы входа.
Только последняя ссылка подтверждения действительна, повторно её использовать нельзя.
Новые аккаунты больше не требуют ручного Y/n в терминале.
Старые аккаунты и их существующий статус подтверждения сохраняются без изменений.

## Если frontend запускается отдельно

Например, из папки frontend:

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

Откройте **http://localhost:5500**, задайте в backend/.env:

```
BASE_URL=http://localhost:3001
FRONTEND_URL=http://localhost:5500
```

В `frontend/config.js` оставьте адрес API `http://localhost:3001`.
Перезапустите backend. Разрешается только точный настроенный origin, не `*`.
Не смешивайте `localhost` с `127.0.0.1`: браузерные cookies зависят от адреса.

Для размещения в Интернете используйте HTTPS, `NODE_ENV=production`, корректные
публичные URL и адрес API в `frontend/config.js`. Не оставляйте localhost в письмах
для других устройств. Backend должен быть доступен браузеру.
Сессионные cookies имеют SameSite=Lax: для разных сайтов используйте общий сайт
с обратным прокси. Одного CORS недостаточно для cookies между несвязанными доменами.
Встроенный Python HTTP-сервер предназначен для прототипа, а не промышленной нагрузки.

## API

- POST `/api/auth/register`: name, email, password, role, consent.
- POST `/api/auth/login`: email, password. До подтверждения — 403 `email_not_verified`.
- POST `/api/auth/resend-verification`: email, password.
- GET `/api/auth/verify?token=...`: одноразовое подтверждение, затем переход на frontend.
- GET `/api/auth/me`: текущий пользователь, либо 401.
- POST `/api/auth/logout`: завершение сессии.
- POST `/api/support`: email, message.

Роль организатора пока только поле профиля: API мероприятий и управления ими
в этой версии не добавлены. При их реализации обязательно проверять права на сервере.
Поддержка email не включает восстановление пароля: соответствующая подсказка исправлена.

## Автоматические проверки

Из папки backend:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временную базу, локальный HTTP-сервер и подмену почтового провайдера.
Они не отправляют настоящих писем, не используют вашу базу и не доказывают доставку
через настоящий Resend. Полный сценарий двух разных origins дополнительно проверен
в Chromium при подготовке архива с тестовым почтовым провайдером.
