# Собрались — frontend мероприятий и личного расписания

Самостоятельный frontend на HTML, CSS и JavaScript. Node.js и сборка не нужны.
Внешних библиотек, шрифтов, CDN и картинок из Интернета нет.

## Посмотреть прямо сейчас

Из этой папки в PowerShell:

```powershell
python -m http.server 5500 --bind 127.0.0.1
```

Откройте http://localhost:5500 и нажмите «Посмотреть демоверсию».
Или сразу http://localhost:5500/dashboard.html?demo=1

Терминал сервера должен оставаться открытым. HTML не открывайте как file://.
Это адрес на вашем ноутбуке; размещение для всей команды на сервере — отдельный шаг.

## Что сделано

- Вход: логин и пароль. Регистрации, подтверждения почты и восстановления пароля на страницах нет.
- Учётные записи создаёт организатор в backend. Пароли и список настоящих логинов отсутствуют во frontend.
- Главная: каталог мероприятий, тематики, поиск, сортировка, количество результатов.
- Программа мероприятия: описание и отдельные активности со временем, местом и свободными местами.
- «Моё расписание»: записи по дням, переход к событию и отмена с подтверждением.
- Блок ближайшей активности, статусы участия, пустые состояния и обработка ошибок.
- Мобильная версия, навигация клавиатурой, dialog с Escape и возвратом фокуса,
  сообщения для экранных читалок, поддержка reduced-motion.

## Где демонстрация, а где настоящий вход

Кнопка входа отправляет **настоящий запрос к указанному backend**.
Любой введённый пароль не даёт доступ автоматически.
Отдельная кнопка «Посмотреть демоверсию» открывает только демонстрационный интерфейс.
В нём 6 вымышленных мероприятий, 11 активностей и 2 начальные записи.
Можно отменить все записи: после обновления они не появятся заново.

Демозаписи хранятся в localStorage под ключом `sobralis.demo.registrations.v1`.
Маркер демосеанса хранится в sessionStorage. Пароли в них не записываются.
Чтобы вернуть начальные демозаписи, удалите указанный ключ localStorage в инструментах браузера.
Демо проверяет наличие мест и пересечение времени; соседние интервалы допустимы.
Демо не имитирует надёжность базы, права доступа или конкурентные запросы разных людей.
Эти проверки при настоящей работе обязан выполнять backend.

## Как перенести в GitLab frontend

Сохраните текущую работу. Скопируйте **содержимое** этой папки в корень frontend-репозитория,
сохранив .git, .gitlab-ci.yml и policy.yml. В архиве их нет.
Важны все файлы: index.html, login.html, dashboard.html, style.css,
config.js, api.js, data.js, store.js, login.js, dashboard.js.
Данные программы, адаптер и стили теперь относятся к новой версии — переносите их вместе.
Старые script.js/help.html/help.js не используются новой навигацией; удалять их для запуска не нужно.
Не копируйте эту папку внутрь backend.

## Подключение к backend

В `config.js` укажите публичный адрес API. Пустая строка означает тот же origin
(например, при обратном прокси). Сейчас стоит http://localhost:3001.
Запросы отправляются с credentials: include для cookie-сессии.
Backend должен разрешать точный origin frontend, например http://localhost:5500,
и устанавливать cookies с корректными HttpOnly/SameSite/Secure.
Для разных несвязанных сайтов используйте общий сайт с обратным прокси:
CORS сам по себе не решает ограничения браузера на сторонние cookies.

**Backend из предыдущего архива не изменён. Он ожидал `email`, а новый интерфейс — `login`.**
Кроме того, в прежнем backend нет API мероприятий и расписания.
Поэтому без доработки backend настоящие логины и данные пока не заработают.
Ниже — предлагаемый контракт для согласования с вашей backend-командой;
при другом контракте меняйте `login.js` и `store.js`, а не все страницы.

- POST /api/auth/login: `{ "login": "student01", "password": "..." }`.
  Успех 200 + cookie. Ошибка 401 `{ "error": "Неверный логин или пароль." }`.
- GET /api/auth/me → `{ "user": { "id": "u1", "name": "Имя", "role": "participant" } }`.
  Без авторизации — 401.
- POST /api/auth/logout с `{}` → 200. Завершает сессию на сервере.
- GET /api/events → `{ "events": [...] }`.
- GET /api/activities → `{ "activities": [...] }`.
- GET /api/registrations → `{ "registrations": [{ "activityId": "a11" }] }` только текущего пользователя.
- POST /api/activities/{id}/registrations с `{}` — записать текущего пользователя.
- POST /api/activities/{id}/cancel с `{}` — отменить только собственную запись.
  Эти операции должны возвращать JSON, при конфликте 409 `{ "error": "Причина отказа" }`.

Даты активности передаются в ISO 8601 с часовым поясом; интерфейс показывает время Москвы.
Строковые или числовые ID приводятся к строкам.
Мероприятие: id, title, description, category, date (`YYYY-MM-DD`), location.
Дополнительные поля обложки: coverTitle, coverLabel, color/ink (#RRGGBB), art (rings/spark/blocks).
Активность: id, eventId, title, description, start, end, room, capacity, availableSeats.
При настоящем API `availableSeats` уже учитывает все записи, включая текущего пользователя.
После записи или отмены программа и расписание перечитываются с сервера.
Ответы API не должны содержать хеши паролей или чужие регистрации.

## Проверено

В Chromium: вход без регистрации, явный вход в демо, каталог, поиск и пустой результат,
тематики, сортировка, программа, полная активность, повторная запись, конфликт времени,
соседние интервалы, личное расписание и дни, отмена с подтверждением, обновление страницы,
пустое расписание, общий демосписок в двух вкладках, ошибка настоящего запроса входа.
Ширины 360, 375, 768 и 1440: горизонтального переполнения не обнаружено.
Настоящие вход по базе, backend мероприятий и публикация сайта не проверялись и не включены.
